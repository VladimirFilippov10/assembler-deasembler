================================================================================
ASM WORKSHOP — АССЕМБЛЕР ⇄ ДЕАССЕМБЛЕР x86
================================================================================

Описание проекта, инструкция по сборке, запуску и принципам работы.

--------------------------------------------------------------------------------
1. О ПРОГРАММЕ
--------------------------------------------------------------------------------
ASM Workshop — это кроссплатформенный ассемблер и деассемблер для архитектуры 
x86 (16/32/64 бит). Программа позволяет:

• Собирать NASM-код в машинные байты (ASM → HEX)
• Разбирать машинные байты в инструкции (HEX → ASM)
• Смотреть разбор команды по полям (префикс, opcode, операнды, immediate)
• Работать в режимах COM 16-bit (DOSBox), 16, 32 и 64 бита

Программа имеет два интерфейса:
1. Графический (GTK3, чистый C) — для Linux и macOS.
2. Терминальный (CLI) — для любой ОС.

--------------------------------------------------------------------------------
2. СОСТАВ ПРОЕКТА
--------------------------------------------------------------------------------
Проект написан на языке C (стандарт C99) с использованием GTK3 для GUI.

Файлы:
  • engine.c    — Движок: вызовы NASM, objdump, ndisasm; парсинг, сборка.
  • core.h      — Общий интерфейс между GUI и движком (структуры, прототипы).
  • bdtable.h   — Разбор текстовой таблицы разбора (для GUI и CLI).
  • gui.c       — Графический интерфейс (GTK3).
  • theme.h     — CSS-палитра для GTK3 (бело-синяя тема).
  • cli.c       — Терминальный интерфейс.
  • README.txt  — Этот файл.

--------------------------------------------------------------------------------
3. ТРЕБОВАНИЯ И ЗАВИСИМОСТИ
--------------------------------------------------------------------------------
Для работы программы необходимы внешние утилиты:
  • nasm     — ассемблер (обязательно для ASM → HEX)
  • ndisasm  — деассемблер (входит в пакет nasm; обязателен для HEX → ASM)
  • objdump  — дизассемблер из binutils (опционально, используется для 32/64 бит)

Установка на разных ОС:

  macOS (через Homebrew):
    brew install nasm binutils
    (ndisasm устанавливается вместе с nasm)

  Linux (Debian/Ubuntu):
    sudo apt install nasm binutils build-essential libgtk-3-dev

  Windows (MSYS2):
    pacman -S mingw-w64-x86_64-nasm mingw-w64-x86_64-binutils mingw-w64-x86_64-gtk3

--------------------------------------------------------------------------------
4. КАК СОБРАТЬ
--------------------------------------------------------------------------------
Проект собирается компилятором gcc (или clang).

Сборка GUI-версии (с GTK3):
  gcc -O2 -o asmworkshop gui.c engine.c `pkg-config --cflags --libs gtk+-3.0`

Сборка CLI-версии (без GTK):
  gcc -O2 -o asmworkshop_cli cli.c engine.c

Запуск:
  ./asmworkshop          # графический интерфейс
  ./asmworkshop_cli      # терминальный интерфейс

--------------------------------------------------------------------------------
5. КАК ПОЛЬЗОВАТЬСЯ (GUI)
--------------------------------------------------------------------------------
1. Выберите режим в правом верхнем углу:
   • COM 16-bit (DOSBox, ORG 0x100) — для DOS-программ
   • 16-bit raw — для чистого 16-битного кода
   • 32-bit raw — для 32-битного кода (Windows/Linux)
   • 64-bit raw — для 64-битного кода

2. Левая панель «АССЕМБЛИРОВАНИЕ ASM → HEX»:
   • Введите ассемблерный код (например, mov ax, 0x4C00)
   • Нажмите «Собрать →»
   • Получите HEX-строку в поле результата
   • Таблица «Разбор команды по полям» покажет структуру

3. Правая панель «ДЕАССЕМБЛИРОВАНИЕ HEX → ASM»:
   • Введите HEX-байты (например, B8 00 4C)
   • Нажмите «← Разобрать»
   • Получите ассемблерный код

4. Кнопка «О программе» в правом верхнем углу открывает/закрывает 
   раскрывающийся блок с описанием программы.

5. Горячие клавиши:
   • Ctrl+Enter в поле ввода — запустить сборку/разбор

--------------------------------------------------------------------------------
6. КАК ПОЛЬЗОВАТЬСЯ (CLI)
--------------------------------------------------------------------------------
Запуск: ./asmworkshop_cli

Команды в интерактивном режиме:
  q / quit      — выход
  help          — справка
  !hex          — направление asm -> hex
  !asm          — направление hex -> asm
  !com/!16/!32/!64 — смена режима
  table on/off  — вкл/выкл таблицу разбора
  clear         — очистить экран

Примеры:
  asm→hex> mov ax, 1   ->  HEX : B8 01 00
  hex→asm> B8 01 00    ->  ASM : mov ax, 1

Быстрый запуск из командной строки:
  ./asmworkshop_cli -a "mov ax, 1" -m com
  ./asmworkshop_cli -d "B8 01 00" -m com
  ./asmworkshop_cli -f file.asm -m 32

--------------------------------------------------------------------------------
7. КАК ЭТО РАБОТАЕТ ВНУТРИ
--------------------------------------------------------------------------------

[Сборка ASM -> HEX]
1. GUI/CLI вызывает engine_assemble().
2. Если код содержит метки, движок итеративно собирает префикс кода, чтобы 
   вычислить реальные адреса меток (обычно 2-3 прохода).
3. Формируется полный NASM-исходник (BITS + ORG + SECTION .text).
4. Вызывается NASM: `nasm -f bin -O0 -o out.bin in.asm`.
5. Байты читаются из out.bin и переводятся в HEX-строку через пробел.

[Разбор HEX -> ASM]
1. GUI/CLI вызывает engine_disassemble().
2. HEX-строка парсится в массив байт (parse_hex).
3. В зависимости от режима выбирается инструмент:
   • COM/16-bit: ndisasm (надёжнее для DOS-кода)
   • 32/64-bit: objdump (с fallback на ndisasm)
4. Вызывается утилита:
   • ndisasm -b16 -o0 -u input.bin
   • objdump -D -b binary -m i386 -M intel input.bin
5. Вывод парсится и нормализуется (пробелы, запятые).
6. Для каждой инструкции вызывается insn_split(), которая разбивает 
   её на поля: префикс, opcode, операнды, immediate.

[Таблица разбора]
1. engine_breakdown() вызывает engine_assemble() или parse_hex().
2. Затем disasm_with_sizes() разбирает байты.
3. Формируется текстовая таблица с колонками:
   N | Prefix | Opcode | Operands | Immediate | Size
4. В GUI эта таблица заполняет GtkTreeView, в CLI выводится как текст.

[Поиск утилит]
Движок ищет nasm, ndisasm, objdump через $PATH, а затем в стандартных местах:
/opt/homebrew/bin, /usr/local/bin, /usr/bin, /bin
Это решает проблему запуска из .app на macOS, где $PATH урезан.

[Режимы]
  MODE_COM = 0  — DOS .COM (BITS 16, ORG 0x100)
  MODE_16  = 1  — чистый 16-бит (BITS 16)
  MODE_32  = 2  — 32-бит (BITS 32)
  MODE_64  = 3  — 64-бит (BITS 64)

8. БЛОК «О ПРОГРАММЕ»
--------------------------------------------------------------------------------
Кнопка «ℹ О программе» в шапке окна — это GtkToggleButton. 
По умолчанию блок скрыт (gtk_widget_hide). 
При нажатии:
  • gtk_widget_show_all(about_box) показывает контейнер и всех детей.
  • Кнопка меняет надпись на «Скрыть».
Повторное нажатие:
  • gtk_widget_hide(about_box) скрывает блок.
  • Надпись возвращается к «ℹ О программе».

Содержимое блока:
  • Две колонки: «О ПРОГРАММЕ» и «КРАТКИЙ ГАЙД».
  • Жёлтый вертикальный разделитель.
  • Нижняя плашка с разработчиком.
  • Всё оформлено через CSS-классы в theme.h:
    .aboutbox, .abouttitle, .abouttext, .aboutdev, .aboutsep.

--------------------------------------------------------------------------------
9. ВОЗМОЖНЫЕ ПРОБЛЕМЫ И РЕШЕНИЯ
--------------------------------------------------------------------------------

Проблема: «NASM: nasm завершился с кодом 1»
Решение: проверьте синтаксис ассемблерного кода. Ошибка выводится 
в поле статуса. На macOS проверьте, что nasm установлен (brew install nasm).

Проблема: «Не нашёл ни одного байта в hex-строке»
Решение: HEX-строка должна состоять из hex-символов (0-9, A-F), 
разделённых пробелами или запятыми. Пример: "B8 01 00".

Проблема: На macOS выводится mov eax вместо mov ax
Решение: это баг ndisasm при неправильной передаче флага -b. 
В engine.c флаг передаётся слитно: -b16, -b32, -b64. 
Убедитесь, что у вас актуальная версия engine.c.

Проблема: «ndisasm не найден»
Решение: установите nasm (ndisasm входит в пакет). 
На macOS: brew install nasm. 
На Linux: sudo apt install nasm.

Проблема: objdump не понимает -b binary на macOS
Решение: Apple-версия objdump не поддерживает бинарный режим. 
Движок автоматически переключается на ndisasm для 16-бит, 
а для 32/64 бит использует GNU objdump (brew install binutils).
