# ASM Workshop — полное описание программы

**ASM Workshop** — учебный графический инструмент для работы с машинным кодом
процессоров семейства x86: он **ассемблирует** текст команд в HEX-байты,
**деассемблирует** байты обратно в команды и **разбирает каждую команду по полям**
(префиксы, opcode, модификаторы адресации, immediate, размер).

Разработчик: Филиппов Владимир Евгеньевич, группа 25ПИнж(б)-1.

---

## 1. Для чего нужна программа

При изучении ассемблирования важно видеть связь между человекочитаемой командой
(`mov ax, 0x4C00`) и её машинным представлением (`B8 00 4C`). Программа даёт
три возможности одновременно:

1. **Сборка (ассемблирование)** — ввод asm-листа → получение HEX-кода;
2. **Разбор (деассемблирование)** — ввод HEX-байтов → получение листинга;
3. **Полевой разбор** — таблица, показывающая строение каждой машинной команды:
   номер, префикс, opcode, операнды, immediate-часть и размер в байтах.

Это удобно для лабораторных работ по курсу «Ассемблирование и деассемблирование»,
подготовки .COM-файлов для DOSBox и изучения различий кодирования команд в
16/32/64-битных режимах.

## 2. Варианты реализации

В репозитории два равноценных клиента одного движка:

| Каталог            | Язык / UI toolkit        | Платформа           | Исполняемые файлы |
|--------------------|--------------------------|---------------------|-------------------|
| `asmworkshop/`     | C + GTK 3                | Linux               | `asmworkshop` (GUI), `asmworkshop_cli` (терминал) |
| `asmworkshop-go/`  | Go + WinAPI (lxn/win)    | Windows             | `asmworkshop.exe` (GUI), режим `--cli` на любой ОС |

Обе версии используют одни и те же внешние инструменты:
**NASM** (сборка в бинарный код) и **objdump / ndisasm** (разбор байтов).

### Структура исходников (C-версия, `asmworkshop/src/`)

- `core.h` — общий интерфейс GUI ↔ движок (режимы, структура `Result`, API движка);
- `engine.c` — движок: вызов `nasm`, `objdump`, `ndisasm`, парсинг листинга,
  разбиение команд на поля, русские пояснения к инструкциям (`explain_line`);
- `gui.c` — окно на GTK3: колонки ввода/вывода, таблицы разбора, диалог «О программе»;
- `cli.c` — интерактивный терминальный режим (команды `!hex`, `!asm`, `help`, `q`);
- `bdtable.h` — статическая таблица быстрых пояснений по опкодам;
- `theme.h` — палитра бело-синего стиля интерфейса.

### Структура исходников (Go-версия, `asmworkshop-go/`)

- `engine.go` — порт движка на Go (те же NASM/objdump под капотом);
- `gui_windows.go` — нативное окно Windows (WinAPI): редактируемые поля,
  ListView-таблицы разбора, кнопка «О программе» (модальное MessageBox-окно);
- `mini.go` — упрощённый собственный декодер (используется, когда objdump недоступен);
- `main.go` — точка входа: GUI по умолчанию, флаги `--cli`, `-a`, `-d`, `-f`, `-m`.

## 3. Поддерживаемые режимы

| Режим      | Формат NASM | Особенность                                        |
|------------|-------------|----------------------------------------------------|
| `COM 16`   | `-f bin`    | DOS COM-файл: `ORG 0x100`, запуск в DOSBox         |
| `16-bit`   | `-f bin`    | плоский 16-битный код (real mode)                  |
| `32-bit`   | `-f bin`    | 32-битный код (protected mode)                     |
| `64-bit`   | `-f bin`    | x86-64 код (long mode)                             |

Режим влияет и на сборку, и на разбор: одна и та же последовательность байтов
в 16/32/64-битном режимах деассемблируется по-разному.

## 4. Интерфейс и как пользоваться (GUI)

Окно разделено на две колонки:

**Левая колонка — ассемблирование:**
1. выберите режим в раскрывающемся списке сверху;
2. введите asm-код в поле слева (можно несколько строк — целый мини-листинг);
3. нажмите **«Собрать →»** (или `Ctrl+Enter`) — справа появятся HEX-байты;
4. кнопки **«Копировать HEX»**, **«Вставить»**, **«Очистить»** работают с буфером обмена.

**Правая колонка — деассемблирование:**
1. введите HEX-байты через пробел (`B8 01 00`);
2. нажмите **«← Разобрать»** — получите листинг и пояснение;
3. **«Копировать ASM»** копирует результат в буфер обмена.

**Таблицы «Разбор команды по полям»** (две карточки внизу) показывают для каждой
команды: №, префикс (`rep`/`lock`/нет), opcode, операнды, immediate, размер в байтах.

**Кнопка «результат → поле HEX-ввода»** переносит собранный HEX в правое поле —
быстрый цикл «собрал → сразу разобрал».

**Кнопка «ℹ О программе»** — единственный способ открыть сведения о программе:
по умолчанию этот блок **закрыт**; по нажатию открывается модальное окно с
назначением программы, пошаговой инструкцией и данными разработчика.
Закрывается оно кнопкой «Закрыть»/«ОК» в самом окне (отдельной кнопки «Скрыть» больше нет).

Статусная строка внизу сообщает о готовности результата или об ошибке
(текст ошибки NASM/objdump показывается в панели результатов цветным маркером
✓/✕).

## 5. CLI-режим

**C-версия:** `./asmworkshop_cli` — интерактивный ввод; команды:
`!hex` / `!asm` — смена направления, `com/16/32/64` — смена режима,
`help` — справка, `q` — выход.

**Go-версия (однострочники):**
```bash
asmworkshop -a "mov ax, 1" -m com     # собрать строку
asmworkshop -d "B8 01 00" -m 16       # разобрать байты
asmworkshop -f prog.asm -m 32         # собрать файл
asmworkshop --cli                     # интерактивный режим
```

## 6. Внутреннее устройство движка

1. Введённый asm-текст оборачивается служебными директивами (`BITS 16/32/64`,
   `ORG 0x100` для COM) и записывается во временный файл.
2. Запускается `nasm -f bin`; stderr перехватывается — сообщения об ошибках
   парсятся и показываются пользователю построчно.
3. Полученный бинарь либо отдаётся как HEX-строка, либо разбирается:
   `objdump -D -b binary -mi386 -M addr16,data16(32,64)` или `ndisasm -b 16/32/64`.
4. Строки листинга парсятся: адрес, байты, мнемоника, операнды; из них
   собираются поля таблицы разбора (`insn_split`).
5. К первой мнемонике подбирается короткое русское пояснение
   (`explain_line` + таблица `bdtable.h`).
6. Обратный путь (HEX → ASM): вход нормализуется (пробелы, `0x`, запятые),
   байты проверяются, затем тот же разбор objdump/ndisasm.
7. Если внешних инструментов нет в PATH, Go-версия использует встроенный
   минимальный декодер `mini.go` (базовые MOV/ALU/JMP/CALL/RET/INT).

## 7. Установка, сборка, запуск

### Linux (C + GTK3)
```bash
sudo apt install -y build-essential libgtk-3-dev nasm binutils
cd asmworkshop && ./build.sh
./asmworkshop          # GUI
./asmworkshop_cli      # терминальный режим
```

### Windows (Go + WinAPI)
```bat
cd asmworkshop-go
go build -ldflags "-H windowsgui" -o asmworkshop.exe .
asmworkshop.exe
```
Требуется установленный `nasm` (и при желании `objdump` из binutils) в PATH.

Готовые архивы: `asmworkshop-win64.zip` (Windows x64),
`asmworkshop-all-platforms.zip` (все сборки).

## 8. Пример работы

Ввод (режим COM 16):
```
mov ax, 0x4C00
int 0x21
```
Результат сборки: `B8 00 4C CD 21`

Таблица разбора:

| № | Префикс | Opcode | Операнды   | Immediate | Размер, байт |
|---|---------|--------|------------|-----------|--------------|
| 1 | —       | mov    | ax, 0x4C00 | 0x4C00    | 3            |
| 2 | —       | int    | 0x21       | 0x21      | 2            |

Пояснение: `int 0x21` — вызов прерывания DOS (функция завершения программы — AX=4C00h).

## 9. Известные ограничения

- Одна команда может содержать до ~512 символов вывода (буферы фиксированного размера);
- Полный синтаксис NASM (макросы, `%define`) не гарантирован — ориентир на учебные примеры;
- Go-версия GUI собирается только под Windows (Linux/macOS — режим `--cli`);
- Для корректной работы нужны установленные `nasm` и `objdump`/`ndisasm` в PATH.
